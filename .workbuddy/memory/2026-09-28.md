## co-form-tabs 能力扩展（把「校验失败切页签」做成完整的错误可视链路）

需求：除了"校验失败切到对应页签"，把这套机制能扩展的能力都做掉。

### 基建：FormContext 从「只通知失败」升级为「校验状态变更」

`components/form/form.api.ts` + `useFormTemplate.ts`：

- `onValidateError(handler)` → **`onValidateChange(handler)`**，回调 `(invalidFields, reason)`。
  **通过时也通知**（`invalidFields` 为空对象）—— 否则徽标、完成度这类「错误消失」的能力没法做。
- `reason: 'validate' | 'validate-field' | 'field' | 'reset'`。**只有 `validate` 会切容器 + 滚动定位**；
  打字时 blur 触发的实时校验如果也切，用户每填错一格就被拽走。
- `invalidFields` 改为**从 `el-form.fields` 的 `validateState` 推导全量快照**（`getInvalidFields()`），
  不再用 el-form 回调给的那份 —— 回调里的集合只含「本次校验涉及的字段」，做状态展示会漏。
- 新增 `getFields()` / `validateFields(props, reason)` / `scrollToInvalid()` / `reportFieldChange()`。
- `useFormTemplate` 现在返回 `elFormRef` 和 `formContext`。

`components/form/form-item.vue`：watch `formItemRef.value.validateState` → `reportFieldChange()`。
没有这一步，字段自身的实时校验（blur/change）不会通知出去，徽标不实时。
`reportFieldChange` 里用 microtask 去重（同一批字段一起变只通知一次）。

### 滚动 + 高亮（`useFormTemplate` 统一调度）

`nextTick` → `requestAnimationFrame` → 找**第一个可见的**出错字段（`getClientRects().length > 0`，
按 `compareDocumentPosition` 取文档顺序靠前的）→ `scrollIntoView({block:'center'})` + 加
`is-invalid-flash` 类（`style/form.scss` 里的 `co-invalid-flash` 动画，1.6s 后移除）。

为什么统一在 form 层做：多个容器可能同时响应（切页签 + 展开分组），只能滚一次。
顺序必须是「先让容器切完（同步）→ 等 DOM → 再滚」。

### 四个消费者（共用 `components/form/useFormInvalid.ts`）

| 组件            | 新增能力                                | prop                                  |
| --------------- | --------------------------------------- | ------------------------------------- |
| `co-form-tabs`  | 徽标 + 顶部汇总跳转 + 分步模式 + 完成度 | `showBadge` `showErrorSummary` `step` |
| `co-form-group` | 自动展开含出错字段的分组                | `switchToInvalid`                     |
| `co-form-query` | 收起时自动展开                          | `switchToInvalid`                     |
| `co-form-list`  | 出错行高亮（`is-error`）                | `switchToInvalid`                     |

共享工具：`useFormContext()` / `locateInvalidContainer(invalidFields, fields, containers)` /
`useInvalidResponse(respond, reasons?, formContext?)`。

### 踩的坑（都实测过）

1. **`inject` 不查自身**：`co-form-query` 自己 `provide` 表单上下文，在它内部再 `inject` 只能拿到
   **父级**的（最外层用时 = null）→ 订阅根本没建立，展开失效。
   → `useFormTemplate` 现在返回 `formContext`，`useInvalidResponse` 加了第三个参数显式传入。
2. **`field.propString` 的分隔符是 `.` 不是 `,`**：EP 的实现是
   `isArray(prop) ? prop.join('.') : prop` → form-list 行内字段是 `awards.1.award`。
   一开始按 `,` split，行高亮一直不生效。
3. `reactive({...})` 不能写成 `reactive<FormContext>({...})`（`toRef` 的 Ref 类型不匹配），
   去掉泛型让 TS 推断即可。
4. 页签顺序必须按 **DOM 顺序**（`compareDocumentPosition`）算，注册顺序在
   `v-if` 条件渲染 / `v-for` 重排后会与视觉顺序不一致。

## co-form-tabs 动态页签：移除激活页签会让整个表单体空白（同日，用户提问后实测）

用户问「panel 有条件渲染时，`addPanel` 保留的数据还有用吗 / 会造成影响吗」→ 实测出一个真 bug。

**移除路径原来只做两件事**：`panels.splice` + `nextTick(refreshOrder)`，派生状态一个都没管：

1. ✅ `panels` / `orderedPanels` 会自愈 —— 卸载后 Vue 把模板 ref 置 null，`getEl()` 返回 undefined。
2. ⚠️ **`errorCounts` 里的键留着**，但实测**看不到幽灵徽标**：同名页签重新挂上来时，
   新 `co-form-item` 的 `validateState` watcher（`undefined → ''`）会触发 `reportFieldChange()`
   → `syncErrorCounts()` 全量重建计数，顺手把它冲掉。**这是撞上的，不是设计的** →
   已显式 `delete errorCounts.value[key]`，不再依赖那个巧合。
3. ❌ **当前激活的页签被移除 → 空白态（真 bug）**：el-tabs 停在那个已经消失的 name 上，
   实测 `activeCount: 0` / `visiblePanes: 0` —— **整个表单体 `display: none`，用户看到一片空白**；
   只有「再点一次提交」（`switchToInvalid` 把它拉回来）才能自救。
   → 新增 `ensureActivePanel()`：移除后若激活页签已不存在，`activate(第一个仍存在的页签)`。
   ⚠️ **只能在移除时调，注册时绝对不能调**：多个页签是逐个 setup 注册的，第一个进来时其余还没注册，
   会把「暂时找不到的激活页签」误判成失效，把外部 `v-model` 指定的初始页签冲掉。

**模型里的值不受影响**：`v-if` 摘掉页签只是卸载了字段（校验随之不再覆盖它们），`model` 上的值还在、
提交照样会带上 —— 已写进文档；要「隐藏即清空」得自己处理。

顺带整理结构：`addPanel` 从 `provide({...})` 内联改成具名函数、挪到 `ensureActivePanel` 之后，
`provide` 写在两者之后再调用，去掉前向引用。

**验证**（新 demo `docs/examples/form-tabs/tabs-dynamic.vue` + 文档「动态增删页签」章节）：
空表提交三页签各 1 → 切到「附加信息」→ 隐藏它 → **自动回落基础信息、`visiblePanes: 1`**（修复前是 0）
→ 重新显示无幽灵徽标 → 再提交切页签仍正常 → `tabs-attributes` 的 v-model 外部切换未受影响。
`prettier` / `vue-tsc --noEmit` / `eslint --max-warnings 0` 全绿。

## useTwoWayBinding → vue 内置 useModel（同日，用户提问后落地）

用户问「cosey 中的 `useTwoWayBinding` 是否可以用 vue 内置的 `useModel` 代替」→ 读了 `@vue/runtime-core@3.5.21`
的源码（`runtime-core.esm-bundler.js` 的 `function useModel`）后结论：**可以，而且是超集**。

### 为什么可以

`useModel` 的 `customRef` setter 里有这么一段（关键）：

```js
const rawProps = i.vnode.props;
if (!(rawProps && (name in rawProps || camelizedName in rawProps || hyphenatedName in rawProps) &&
      (`onUpdate:${name}` in rawProps || ...))) {
  localValue = value; trigger();     // 父级没绑 v-model → 退回组件内部状态
}
i.emit(`update:${name}`, emittedValue);
```

也就是说它**同时**覆盖了两种语义：父级绑了 `v-model` → 受控、等回写；父级没绑（或只单向传
`:model-value`）→ 自动退回本地状态。这正是 `useTwoWayBinding` 手写的 `privateValue` 想做的事，
但后者**不论父级绑没绑都自己存一份**，会和 prop 短暂不一致；而且它用默认 `flush:'pre'` 的 `watch` 同步 prop，
`useModel` 用的是 **`watchSyncEffect`（同步）**。另外白拿 `hasChanged` 去重、`.trim`/`.number` 修饰符。

### 改了哪些

- `components/form-tabs/form-tabs.tsx`、`components/form-query/form-query.tsx`、
  `components/form/useBubbleTemplate.tsx` → `useModel(props, 'modelValue' | 'collapsed')`。
  form-query 的 `emit` 因此变成未使用，从 `setup(props, {...})` 的解构里摘掉。
- `hooks/useTwoWayBinding.ts` **保留**（`cosey` 已发布到 npm 1.2.0，`cosey/hooks` 是事实公开子路径，
  删公开导出要等大版本），只补 `@deprecated` JSDoc 写清差异与「`useModel` 需要活跃实例」的代价。

### 两个必须记住的代价

1. **`useModel` 依赖 `getCurrentInstance()`** → 只能在 `setup()` 里**同步**调用。
   `useBubbleTemplate` 现在有这个约束（原来没有），已在注释和文档里写明。
   dev 下拿不到实例会 `warn` 并返回空 `ref()` → **静默失效**（弹窗打不开）。
2. **受控但父级不回写**会失效：写 `v-model` 绑到只读 `computed` 时组件等一个永远不来的回写；
   原来的实现因为自己存值反而能切。属边缘用法，已在 `form-tabs.md` 写明。

### 真机验证（vitepress 5174，验证完已关站清场）

- **不受控**（`tabs.vue` / `tabs-dynamic.vue` 没绑 v-model）：填好第一页 → 徽标消失 → 提交**自动切到账号信息**
  且 `visiblePanes: 1`。这条是 `useModel` 回退语义的核心用例。
- **受控**（`tabs-attributes.vue` 绑 `v-model="activeTab"`）：外部切换 ✅、提交自动切页签 ✅。
- 弹窗内页签：空表提交两页各 2 徽标 → 取消 → 重开回第一页且徽标/错误清空 ✅。
- `form-dialog` / `form-drawer` / `useUpsert` / `useOuterUpsert`：打开 → 取消关闭 → 重开 → 空表确定不关 →
  填好确定关闭 → 编辑回填 → 取消后新增重置，全过 ✅。
- `form-query`（**没绑** `v-model:collapsed`）：提交空表 → `hiddenItems 7 → 0`、高度 50 → 250，自动展开还在 ✅。
- 控制台无任何 Vue 警告（专门 `console --clear` 后复现过一遍才读的）。
- `vue-tsc --noEmit -p tsconfig.app.json` / `eslint --max-warnings 0` / `prettier` 全绿；`tsx useUpsert.test.ts` 7/7。

### ⚠️ 验证时踩的坑（写进技能了）

1. **el-dialog 关闭后 DOM 不消失**（没开 `destroy-on-close`）→ `!!document.querySelector('.el-dialog')`
   判断「有没有关掉」是**假阳性**。必须用 `getClientRects().length > 0`（或 overlay 的可见性）判断。
   我第一次就被骗了一轮。
2. **上一个探针留下的弹窗会污染下一个探针**：`use-outer-upsert.vue` 里嵌的是 `user-upsert.vue`，
   页面因此有**两套**「新增/编辑」按钮 + 两个 dialog 实例。按 `textContent` 找按钮会拿到第一套；
   找「当前打开的弹窗」必须取**可见的那个** overlay，并且换页面/换用例前先 `open` 重载。

## 新增 CoFormSteps / CoFormStep（基于 ElSteps 的分步容器）

用户此前明确「分步不要耦合在 tabs 里，单独做 co-form-steps」→ 这次落地。

### 结构

- `packages/cosey/components/form/useFormContainers.ts`（新）：把 form-tabs 里的
  **容器注册 / 按 DOM 文档顺序排序 / 出错字段计数 / 按容器校验** 抽成共享 composable。
  tabs 与 steps 都用它。校验内部走 `validate-field` 而不是 `validate`（`validate` 会把容器切到
  「第一个含出错字段的容器」→ 点下一步反而被拽回别的步骤）。
- `form-steps.tsx`（`CoFormSteps`）：`ElSteps` 高阶，`v-model` 是当前步骤序号（`useModel`），
  自研 `next/prev/goTo/validateCurrent`，`expose` 同签名。
- `form-step.vue`（`CoFormStep`）：只负责把自己注册进去 + 按 `isActive` 决定渲染不渲染内容。
  标题栏（title/description/icon/status + 两个插槽）由父组件读 entry 后统一渲染成 `el-step`。

### 弹窗 / 抽屉接入（关键设计）

`FormBubbleContext` 加 `registerSteps(getContext)`：`useBubbleTemplate` 的**确定按钮**在
非最后一步变成「下一步」，并补一个「上一步」。steps 自己发现处于弹窗内就**不渲染操作区**
（`showActions = !!slots.actions || !formBubbleContext`）—— 避免两套按钮打架（正是
当初砍掉 tabs 分步模式的理由）。

### 实测踩到的坑（浏览器真机）

- ⚠️ **`el-step` 的状态是内部缓存的，只在 `active` 变化时重算** → 步骤被 `v-if` 增删导致
  **序号整体挪位**后，挪到前面的步骤状态不更新，会停在 `wait`。修：自己按「序号 vs 当前序号」
  算 `status`（显式 `status` 优先 > error > finish > process > wait）。
- ⚠️ 光改状态还不够：**进度线**（`.el-step__line-inner` 的 width）也缓存在 `el-step` 内部 →
  `key` 必须带上序号：``key={`${entry.uid}:${index}`}``，否则增删后线的长度不对。
- `el-step` **没有声明 `click` 事件** → 直接写 `onClick={...}` 过不了类型检查，展开写
  `{...{ onClick: ... }}`。（`el-tab-pane` 同理的老问题。）
- `resetOnOpen`（默认开）：订阅 `formContext.onOpen`，重新打开弹窗复位到第一步。
- 移除步骤后要 `ensureActive()` 把序号夹回范围；**只在移除时调，注册时不能调**（理由同 tabs）。

### 验证结论

vue-tsc / eslint / prettier 全绿。真机跑通：基础翻页+校验拦截、弹窗（footer
`[下一步,取消]` → `[下一步,上一步,取消]` → `[确定,上一步,取消]`，末尾提交成功关闭并弹「操作成功」）、
抽屉、受控 `v-model` / `simple` / `clickable`、动态增删步骤后状态与进度线正确。
form-tabs 回归全过（徽标、动态增删、弹窗内复位、确定提交成功关闭）。

## 修正：分步表单「提交/重置」与「上一步/下一步」并存

用户反馈基础用法里 `co-form` 的「提交+重置」和 `co-form-steps` 的「上一步/下一步」同时出现。

先调研行业做法（Ant Design Steps 官方示例 / HPE / PatternFly Wizard / fomr / Primeforms），
结论一致：**按钮由分步容器按当前位置条件渲染**——首步只有「下一步」，中间「上一步+下一步」，
最后一步「上一步+提交/完成」，不存在两套按钮并存。

### 修法（贴合行业惯例）

- `FormContext` 补三个字段：`submit`（getter 延迟取，因为 `submit` 声明在 formContext 之后）、
  `submitting`、`setHasSteps(boolean)` + 只读 `hasSteps`。
  ⚠️ `submit`/`submitting` 在 `useFormTemplate` 里声明在 `formContext` 之后（const 不提升），
  所以 formContext 里用 **getter** 包（`get submit() { return submit }`）——闭包延迟到调用时解析。
- `co-form-steps`：`actionContext`/`expose` 增加 `submit`/`submitting`；非弹窗下
  `onMounted` 调 `formContext.setHasSteps(true)`、`onBeforeUnmount` 恢复 false；
  默认操作区最后一步渲染「提交」按钮（`submitText`/`submitProps`，loading 接 `submitting`）。
- `co-form`（form.tsx）：按钮行条件加 `&& !formContext.hasSteps`，分步接管后自动收起。

### 验证（浏览器真机）

基础用法按钮流：`[下一步]` → `[下一步,上一步]` → `[提交,上一步]`，`co-form` 按钮行全程为空；
最后一步「提交」调 `formContext.submit()` 走完整校验+`props.submit`，成功弹「提交成功」。
弹窗场景回归正常（`ownActions:0`，footer 由弹窗提供）；form-tabs 回归正常（tabs 不接管提交，
`co-form` 的「提交+重置」行保留）。vue-tsc / eslint / prettier 全绿。
